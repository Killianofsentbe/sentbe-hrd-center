## Slide 03 — Claude Code란 무엇인가?

**제목:** Claude Code = 터미널에서 동작하는 AI 코딩 어시스턴트
**핵심 메시지:** Claude Code는 자연어로 말하면 코드를 대신 써주는 AI입니다.

**본문:**
- Anthropic이 만든 터미널 기반 AI 도구 (2025년 5월 정식 출시)
- 자연어로 요청하면 파일 읽기·쓰기·수정을 자율 수행
- 프로젝트 전체 맥락을 이해해 복잡한 멀티파일 작업도 가능
- IDE 플러그인이 아닌 CLI(터미널 명령줄) 도구
- 전 세계에서 가장 널리 채택된 AI 개발 도구 중 하나

**발표자 노트:**
"쉽게 비유하면, Claude Code는 '내 컴퓨터 안에 앉아있는 AI 개발자'입니다. 제가 한국어로 '이 파일 정리해줘'라고 하면, Claude가 직접 파일을 열고 수정하고 저장합니다."

## Slide 04 — 지원 환경 확인

**제목:** 내 컴퓨터에서 쓸 수 있을까?
**핵심 메시지:** macOS, Ubuntu, Windows(WSL) 환경이라면 바로 시작할 수 있습니다.

**본문:**
- macOS 10.15 (Catalina) 이상
- Ubuntu 20.04 이상 / Debian 10 이상
- Windows: WSL(Windows Subsystem for Linux) 설치 필요
- 공통 필수 조건: Node.js 18 이상 설치
- 회사 지급 맥북은 대부분 바로 사용 가능

**발표자 노트:**
"맥북 사용자는 거의 바로 시작할 수 있습니다. Windows 사용자는 WSL 설치가 필요한데, IT팀에 요청하시면 도움받을 수 있습니다."

## Slide 05 — 설치 및 시작 (2단계)

**제목:** 설치부터 실행까지 딱 2단계
**핵심 메시지:** 명령어 두 줄이면 Claude Code가 실행됩니다.

**본문:**
- 1단계: 터미널 열기 → `npm install -g @anthropic-ai/claude-code` 입력
- 2단계: 작업 폴더로 이동 → `claude` 입력 후 Enter
- 설치 완료 후 Anthropic 계정 연결 (최초 1회)
- 실행되면 프롬프트 창이 열리며 대화 시작 가능
- 막히면 `/doctor` 명령어로 설치 상태 진단

**발표자 노트:**
"터미널이 낯설더라도 괜찮습니다. 명령어를 그대로 복사해서 붙여넣기하면 됩니다. 설치 중 오류가 발생하면 `/doctor`를 입력해보세요. 자동으로 문제를 진단해줍니다."

## Slide 06 — CLAUDE.md: AI 팀원에게 건네는 설명서

**제목:** CLAUDE.md = Claude에게 주는 프로젝트 안내서
**핵심 메시지:** CLAUDE.md 하나로 매 세션의 반복 설명을 없앨 수 있습니다.

**본문:**
- 프로젝트 루트 폴더에 생성하는 마크다운 파일
- `/init` 명령어 한 번으로 초안 자동 생성
- 담을 내용: 빌드 명령어, 코딩 스타일, 주요 폴더 설명
- 없으면? — 매 세션마다 Claude가 처음부터 파악 → 토큰 낭비
- 핵심만 간결하게 (너무 길면 Claude가 중요 규칙을 놓침)

**발표자 노트:**
"신입사원에게 '우리 팀 규칙집'을 주는 것과 같습니다. 한 번만 잘 써두면 이후에는 Claude가 알아서 맥락을 이해합니다. `/memory` 명령어로 언제든지 수정 가능합니다."

## Slide 07 — Plan Mode: 초보자의 안전장치

**제목:** Plan Mode를 켜면 Claude가 먼저 계획을 보여줍니다
**핵심 메시지:** 실행 전에 계획을 확인하는 것이 초보자의 가장 강력한 무기입니다.

**본문:**
- 활성화 방법: `Shift+Tab` 두 번 누르기 또는 `/plan` 입력
- Claude가 문제를 분석하고 단계별 계획을 먼저 제시
- 사용자가 계획을 확인·승인한 뒤에야 실행
- "계획에 더 많은 시간을 쓸수록 성공 확률이 높아진다"
- 하나만 기억한다면 이것: 항상 Plan Mode로 시작하기

**발표자 노트:**
"집 공사를 시작하기 전에 설계도를 먼저 보는 것과 같습니다. Claude가 '이렇게 할게요'라고 보여주면 '좋아요' 또는 '아니요, 이 방향으로 바꿔줘'라고 답할 수 있습니다."

## Slide 08 — 핵심 슬래시 명령어 9가지

**제목:** 꼭 알아야 할 슬래시 명령어 9가지
**핵심 메시지:** `/`로 시작하는 명령어 9개가 Claude Code의 핵심 조작법입니다.

**본문:**
- `/init` — CLAUDE.md 초안 자동 생성
- `/plan` — Plan Mode 진입 (계획 먼저, 실행 나중)
- `/clear` — 대화 초기화 (새 작업 시작 시 필수)
- `/compact` — 대화 요약으로 컨텍스트 절약
- `/context` — 현재 컨텍스트 사용량 시각 확인
- `/memory` — CLAUDE.md 파일 편집
- `/doctor` — 설치 상태 진단
- `/help` — 전체 명령어 목록 확인
- `/exit` — Claude Code 종료

**발표자 노트:**
"명령어 외울 필요 없습니다. `/`를 입력하면 자동완성 목록이 뜨고, `Tab` 키로 선택할 수 있습니다. 처음에는 `/clear`, `/plan`, `/compact` 세 개만 익히세요."

## Slide 09 — 키보드 단축키 & 쉘 명령

**제목:** 키보드 4개와 느낌표(!) 하나로 효율이 3배
**핵심 메시지:** 단축키와 쉘 명령 활용이 초급과 중급의 차이를 만듭니다.

**본문:**
- `Shift+Tab` — 모드 순환: 일반 → Auto-accept → Plan Mode
- `Esc` — 작업 즉시 중단 (컨텍스트는 유지됨)
- `Tab` — `/` 입력 후 명령어 자동완성
- `!명령어` — 쉘 명령 즉시 실행 (예: `!git status`, `!npm test`)
- `!` 명령 결과가 컨텍스트에 포함 → Claude가 보고 즉시 판단

**발표자 노트:**
"`Esc`는 Claude가 잘못된 방향으로 가고 있을 때 즉시 멈출 수 있는 비상 정지 버튼입니다. 컨텍스트가 유지되기 때문에 멈추고 방향을 바꿔 계속 이어갈 수 있습니다."

## Slide 10 — 좋은 프롬프트 vs 나쁜 프롬프트

**제목:** 요청을 구체적으로 할수록 Claude의 결과가 정확해집니다
**핵심 메시지:** 대상 파일명 + 기술 스택 + 요구사항 = 좋은 프롬프트의 공식입니다.

**본문:**
- 나쁜 예: "로그인 버튼 고쳐줘" (신규 사용자 85%가 이렇게 시작)
- 좋은 예: "src/components/LoginButton.tsx에서 API 500 에러 시 메시지가 표시 안 되는 버그 수정 (React 18, TypeScript, axios 사용 중)"
- 공식: [파일 경로] + [문제 상황] + [기술 스택] + [비즈니스 제약]
- 피드백 루프: 테스트·스크린샷·예상 출력을 함께 제공하면 성공률 급상승
- 이미지 드래그 앤 드롭으로 UI 스크린샷도 첨부 가능

**발표자 노트:**
"Claude는 맥락이 없으면 추측해서 답합니다. 구체적인 정보를 줄수록 추측이 줄어들고 정확한 결과가 나옵니다. 처음에는 번거롭게 느껴지지만 수정 횟수가 훨씬 줄어듭니다."

## Slide 11 — 초보자가 자주 하는 실수 (상위 4개)

**제목:** 이 네 가지 실수만 피해도 시간이 절반으로 줄어듭니다
**핵심 메시지:** 자주 하는 실수를 미리 알면 헤매지 않아도 됩니다.

**본문:**
- 실수 1: 모호한 프롬프트 — 파일명, 기술 스택 없이 막연하게 요청
- 실수 2: CLAUDE.md 없이 시작 — 매번 처음부터 파악 → 토큰 낭비
- 실수 3: 한 번에 너무 많은 변경 요청 — 작업을 작은 단계로 쪼개기
- 실수 4: 같은 맥락에서 반복 교정 — 두 번 실패 시 `/clear` 후 재시작

**발표자 노트:**
"가장 흔한 실수는 실수 1번과 3번입니다. '로그인 고쳐줘'처럼 막연하게 말하거나, '전체 시스템 리팩토링해줘'처럼 너무 큰 작업을 한 번에 요청하는 것이 가장 많은 실패의 원인입니다."

## Slide 12 — 초보자가 자주 하는 실수 (하위 4개)

**제목:** 나머지 네 가지 실수도 반드시 기억하세요
**핵심 메시지:** Auto-Accept와 결과 검증 습관이 실수를 막는 마지막 방어선입니다.

**본문:**
- 실수 5: "Kitchen Sink" 세션 — 무관한 작업을 한 세션에 혼재
- 실수 6: Auto-Accept 무분별 사용 — 중요 작업은 수동 검토 필수
- 실수 7: 결과물 검증 스킵 — 테스트 없이 코드를 그냥 사용
- 실수 8: 수정 이유를 파악하지 않음 — 동일 실수 반복 야기

**발표자 노트:**
"Auto-Accept는 편리하지만 핵심 기능에 쓰면 예상치 못한 변경이 생길 수 있습니다. Claude가 수정한 이유를 설명해달라고 요청하는 습관을 들이면 실력도 빠르게 늘어납니다."

## Slide 13 — 실전 팁 TOP 5

**제목:** 파워 유저들이 검증한 핵심 팁 다섯 가지
**핵심 메시지:** 이 다섯 가지 습관만 들여도 생산성이 40% 이상 향상됩니다.

**본문:**
- 팁 1: 피드백 루프 구축 — 테스트·스크린샷 포함이 가장 레버리지 높은 팁
- 팁 2: 항상 Plan Mode 먼저 — 하나만 기억한다면 이것
- 팁 3: `/clear` 자주 사용 — 새 작업마다 초기화로 컨텍스트 최적화
- 팁 4: `/compact`로 긴 세션 관리 — 30분 이상 세션은 요약 필수
- 팁 5: 쉘 명령(`!`)으로 실시간 컨텍스트 제공 — Claude가 결과를 보고 즉시 행동

**발표자 노트:**
"이 다섯 가지를 익힌 파워 유저들은 생산성이 최대 40% 향상된다고 합니다. 오늘부터 Plan Mode와 `/clear`만 먼저 적용해보세요."
